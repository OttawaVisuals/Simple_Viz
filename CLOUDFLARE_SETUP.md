# Cloudflare Pages setup

The site stays static. Cloudflare Pages Functions handles only `/api/feedback`, and D1
stores private feedback.

## 1. Create the database

In the Cloudflare dashboard:

1. Go to **Storage & databases → D1 SQL database**.
2. Create a database named `madeclear-feedback`.
3. Open its **Console**, paste `migrations/0001_feedback.sql`, and run it.

## 2. Bind D1 to the Pages project

1. Go to **Workers & Pages → madeclear.ca → Settings → Bindings**.
2. Add a **D1 database binding**.
3. Set the variable name to exactly `FEEDBACK_DB`.
4. Select `madeclear-feedback`.
5. Add the binding to both Production and Preview if feedback should work in previews.

## 3. Add the privacy secret

1. In the Pages project, go to **Settings → Variables and Secrets**.
2. Add an encrypted secret named exactly `FEEDBACK_HASH_KEY`.
3. Use a long random value generated by a password manager.
4. Add a different value to Preview if desired.

The secret creates a one-day duplicate-control key from request metadata. Raw IP addresses
and user-agent strings are never stored.

## 4. Configure email routing

Under **Compute → Email Service → Email Routing**, add `hello@madeclear.ca` and forward it
to the same verified destination currently used by `simon@madeclear.ca`.

## 5. Deploy and test

Push the repository through the existing Pages deployment. On a visualization page:

1. Select a clarity rating.
2. Optionally add a comment.
3. Submit.
4. Confirm the row appears in the D1 Console:

```sql
SELECT page_slug, rating, comment, context_json, submitted_at
FROM feedback
ORDER BY submitted_at DESC
LIMIT 20;
```

Feedback comments are private because the site exposes no read endpoint. Access is through
the authenticated Cloudflare dashboard only.
